# ADR 0013：既有服務遷移到 Caloud

- 狀態：Accepted
- 日期：2026-11-11
- 相關需求：FR-MIG-01～10

## 背景

用戶要把運作中的服務搬到 Caloud，例如 iSunFA：
- 網域：`isunfa.com`
- 資料：PostgreSQL 加上檔案
- 帳號：以 Passkey 登入，WebAuthn origin 綁定 `https://isunfa.com`

搬家後必須確認兩件事：舊帳號能正常操作，資料沒有遺失。

## 決策

1. **網域先驗證、後切換**：自訂網域只用 TXT 驗證擁有權，舊站照常服務。用戶新增 `_acme-challenge.<網域>` CNAME，委派到 Caloud 的隨機名稱，Caloud 以 DNS-01 預先取得憑證，切換當下 TLS 已就緒。
2. **舊主機裝 `caloud-agent --migrate`**：用一次性遷移權杖、只往外連線，由它負責：
   - 執行 `pg_dump`／`mysqldump`。
   - 以 tar 串流傳送檔案目錄。
   - 計算來源端的比對雜湊。
   - 執行用戶設定的凍結指令。

   不需要把舊資料庫開放對外連線。
3. **演練可重複**：快照還原到專用遷移環境（12 字元子網域），在那裡執行驗證與資料比對。
4. **資料比對**：
   - 資料表：每張表的筆數、依主鍵排序的內容雜湊、序列值。
   - 檔案：路徑、大小、SHA-256。
   - 來源端與目標端分別計算；任何遺失或不符都是 Blocker，未全數通過不能切換。
5. **帳號驗收用 hosts 預覽**：
   - Passkey 綁定精確的 origin，在 caloud.tw 子網域上無法登入。
   - 平臺提供 Edge IP 與 hosts 設定，用戶只在自己電腦把網域指到 Caloud，就能用真網域與 Passkey 登入遷移環境。
   - 用戶依驗收清單逐項勾選，其他用戶仍在舊站。
6. **切換用寫入凍結**：
   - 預先把 TTL 降到 60 秒。
   - 舊站切唯讀或維護頁。
   - 最後同步並再次比對，全數通過後由用戶改 DNS。
   - 切換後監控 30 分鐘。

   停機時間約等於最後同步的時間。
7. **回退**：舊站至少保留 7 天，回退即 DNS 指回舊站；切換後新增的資料可以匯出供回寫。

## 考慮過的方案

| 方案 | 優點 | 缺點 |
| --- | --- | --- |
| **寫入凍結＋最後同步**（採用） | 簡單、可精確比對；不需要舊庫特殊設定 | 數分鐘停機 |
| 邏輯複寫（零停機） | 不停機 | 舊庫要開 logical replication 與高權限；比對時資料仍在變動；實作複雜 |
| 只接受上傳備份檔 | 平臺最簡單 | 最後同步與來源端比對要用戶手動做，容易出錯 |
| 切換後才驗收帳號 | 不需 hosts | 有問題時已影響所有用戶，只能回退 |

## 影響

- `caloud-agent` 增加遷移模式（[06 §6.2](../06-api-spec.md#62-遷移模式草案m7-12-實作時定稿)）。
- 新增資料表 `migrations`、`migration_checks`（M7）。
- 新增工作項目 M7-11～15。
